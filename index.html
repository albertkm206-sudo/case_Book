Executive Summary

Casebook collects customer information conversationally, validates key fields, stores cases locally, and allows customers to review their information before submission. The admin console exposes operational details separately from the customer experience.

Prototype Architecture

Customer UI → Chatbot extraction → Validation → Review/Edit → Local Storage → Section Worker Queue → Worker Review → Resolved Case / Customer Cases / Admin Console.

Storage sections:

✓ casebook_cases — submitted cases

✓ casebook_customers — customer details

✓ casebook_evidence — uploaded photos

✓ casebook_conversations — chatbot messages

✓ casebook_audit — decision records

✓ casebook_notifications — worker notifications

✓ Pre-recorded verification data — section-specific reference records used for legitimacy checks

✓ Worker credentials — demo credentials are embedded in this client-only prototype; use a backend for real security.

This prototype requires no server, Java, Maven or MySQL.
